# Rust 모의매매 SQLite 원장 저장소

## 범위
`core::paper_store`는 독립적인 Rust 모의매매 원장을 파일에 저장하고 복구한다.
Worker, 대시보드, 기존 Python 원장, 거래소 private API에 연결하지 않는다.
실제 주문은 여전히 비활성이다.

## 저장 및 복구 계약
- `PaperStore::create(path, ledger_id, config)`: 새 파일만 생성한다.
  기존 파일과 심볼릭 링크는 덮어쓰지 않는다. 초기화 실패 파일은 삭제하지 않는다.
- `PaperStore::open(path, ledger_id, config)`: 기존 파일, 원래 ID와 정확히 같은
  설정, 지원하는 스키마 버전을 요구한다. 없거나 손상된 DB를 초기화하지 않는다.
- 하나의 DB는 하나의 고정 quote asset 모의 계좌다. 별도 계좌는 별도 DB를 사용한다.
- 설정 및 스키마에 결합한 genesis SHA-256, 이벤트 순번과 이전 해시, canonical JSON,
  현재 head 순번/해시를 검증한다. 순서/누락/중복/충돌/잘못된 체결은 재생을 거부한다.
- `apply`는 먼저 SQLite writer lock을 확보하고 최신 저널을 검증·재생한다.
  이벤트와 head를 동일 트랜잭션에 기록한다. 실패 시 둘 다 취소된다.
  서로 다른 핸들의 동시 쓰기도 같은 DB에서는 직렬화된다.
- 같은 ID와 같은 내용의 재전송은 no-op, 동일 ID의 다른 내용은 오류다.
  성공 여부를 알 수 없는 commit 후에는 새 ID를 발행하지 말고 같은 ID로 재시도한다.
- `audit`는 일관된 읽기 트랜잭션에서 재생한 계좌 상태와 검증된 head를 반환한다.
  예약금, 수량, 실현 손익 및 매수 중단 상태는 별도 가변 스냅샷에서 복사하지 않는다.

## 운영 제한
- 로컬 파일 시스템에서 SQLite WAL 및 synchronous=FULL 사용. DB 파일과 WAL을
  임의로 분리/복사하거나 hard link, 별칭 경로, 네트워크 파일 시스템으로 열지 않는다.
  안전한 온라인 백업/복원 도구 및 장애 주입 기반 전원 손실 검증은 후속 작업이다.
- 해시 체인은 우발적인 변경·일부 누락을 검출하기 위한 것으로 서명/인증이 아니다.
  공격자가 DB 전체를 다시 해싱하거나 head까지 함께 이전 버전으로 되돌린 경우
  외부의 신뢰 가능한 head 없이는 검출할 수 없다. 독립적인 외부 체크포인트가 필요하다.
- 버전 1은 전체 재생 방식이며 최대 2,048 이벤트, 이벤트 JSON 최대 4,096바이트다.
  한도 초과 신규 이벤트는 거부한다. 동일 이벤트 재전송은 먼저 확인한다.
  증분 재생, 스냅샷 체크포인트, 장기 저널 및 데이터 마이그레이션은 미구현이다.
- 이 API는 합성 입력 전용 개발 경로다. 상품별 단위 정규화, 실제 시세 신선도,
  미실현 손익/일중 위험 한도, 시장가 체결 모델, 장기 운영 검증이 필요하다.

## 검증 명령
```sh
cd apps/server
cargo test --locked --test paper_ledger_test
cargo test --locked --test paper_store_test
cargo test --locked
```

추가한 테스트는 재시작/부분 체결/중단 복구, 초기화 금지, 설정/ID 불일치,
이벤트 변조·누락·순서·버전·head 검증, 트랜잭션 실패 후 재시도, 동시 예약과
중복 이벤트 재전송을 대상으로 한다. 위는 실행 방법이며 통과 결과가 아니다.
