## 주문 상태 규칙

- Pending/Open/PartiallyFilled를 아직 해결되지 않은 주문으로 조회한다.
- 요청 수량·가격·종목·방향·주문 종류·생성 시각은 업데이트로 변경할 수 없다.
- NaN, 무한대, 음수, 초과 체결, 체결량 감소, 과거 시각, 잘못된 수수료 정보를
  거부한다. 실패 시 기존 주문의 어느 필드도 바뀌지 않는다.
- 양수 체결에는 유효한 평균 가격이 필요하다. 추가 체결은 누적 거래대금을
  증가시켜야 하며, 체결량이 같을 때 평균 가격을 덮어쓸 수 없다.
- 이미 알려진 거래소 ID는 교체·삭제할 수 없다. 누적 수수료는 감소·삭제하거나
  자산을 바꿀 수 없다.
- Filled/Canceled/Failed는 종료 상태다. 이후 같은 내용의 관측은 무변경 처리하며
  주문을 다시 열거나 나중에 다른 체결 정보를 덮어쓰지 않는다.
- 검증과 갱신은 주문별 잠금 안에서 수행한다. 동일 복원은 허용하고 상충 복원은
  기존 값을 보존한 채 거부한다.

이것은 `f64`를 사용하는 메모리 상태 관리다. 정확한 화폐 원장, 거래소 식별자의
실제 출처·계좌 귀속 확인, 주문 간 경제적 중복 조정, 실계좌 재조정 기능은 아니다.

최종 로컬 `cargo test --locked` 결과는 **46개 통과, 실패 0개, 컴파일 경고
0개**다. 구성은 CLI 8개, 기존 통합 2개, 주문 관리 19개, 실행 경계 11개,
DB 복원 경계 6개다. 이전 기준 10개에서 회귀 테스트 36개가 추가되었다.

주문 테스트에는 256개 동시 생성, 32개 누적 업데이트 경합, 32개 상충 복원,
36가지 상태 전이 조합, 실제 임시 SQLite 저장·재조회·복원이 포함된다.
DB 테스트는 방향 2종 × 주문 종류 4종 × 상태 6종의 **48개 정상 조합**을
왕복 저장하고, 그중 미해결 주문 24개만 다시 조회하는 것도 확인한다.

실행 경계 테스트는 실제 어댑터 메서드와 설정 검증을 호출한다. Worker의 Live
거부는 비어 있는 전용 임시 디렉터리의 실제 실행 파일로 검사하여 `data` 생성
전 중단을 확인한다. 실제 master 또는 그 전역 소켓을 실행 테스트에 사용하지
않았으며, master의 초기 검증 순서는 코드 검토 대상으로 확인한다.

도구 체인은 기존 Docker와 같은 **Rust 1.99.0**이다. `Cargo.lock`, 의존성,
CLI 옵션과 컴파일 경고 오류화 설정은 유지한다. Docker 빌더에는 새 테스트가
사용하는 기존 설정 파일을 복사하는 단계만 추가한다.

독립 검토는 1차 통합 상태를 읽고 비밀값 오류 노출·NULL 오해석 두 가지 중요
결함을 실제 코드로 재현했다. 세 회귀 테스트를 먼저 실패시킨 뒤 수정하고
전체 46개 테스트의 재통과를 확인했다. 검토 이후 별도 재검토 승인으로
표기하지 않으며, 수정 결과의 근거는 실패 재현과 최종 통합 테스트다.

검토의 경미한 후속 항목은 어댑터 오류에 주문 본문이 섞이지 않는지를 별도
센티넬로 검사하는 테스트 보강이다. 현재 구현은 전달된 주문을 출력하지 않고
고정 문구만 반환한다. 기존 테스트는 비밀값 노출 여부와 미구현 동작 거부를
확인한다.

최종 `cargo build --release --locked`도 성공했고 컴파일 경고는 0개였다.
최적화된 실행 파일의 기본/master/worker/deploy/migrate 도움말 5개를 비어 있는
임시 디렉터리와 최소 환경에서 실행해 모두 종료 코드 0, 표준 오류 0바이트,
파일 생성 0개를 확인했다. 변경한 Rust 파일 12개의 rustfmt 검사도 통과했다.
