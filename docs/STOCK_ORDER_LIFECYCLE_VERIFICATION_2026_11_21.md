이번 변경은 영속적인 오프라인 주식 주문 이벤트 저널, KIS VTS의 읽기 전용

## 합성 시나리오의 계산 결과

[`고정 합성 입력`](../config/examples/synthetic_stock_order_events.json)으로
실제 SQLite DB를 만들고 단계마다 닫았다 다시 열었다. 기록 14개에는 서로 다른
이벤트 ID로 반복 전달한 동일 체결도 들어 있지만, 고유 체결은 4건이다.

| 항목 | 매수 주문 | 매도 주문 |
| --- | --- | --- |
| 예약 수량 | 10주 | 5주 |
| 체결 수량 | 3주 + 2주 | 2주 + 3주 |
| 체결 대금 | 49,700원 | 55,200원 |
| 수수료 | 50원 | 55원 |
| 세금 | 0원 | 110원 |
| 최종 상태 | `canceled` | `filled` |
| 최종 미체결 수량 | 5주 | 0주 |
| 최종 유효 주문 수량 | 0주 | 0주 |

합계 현금 변화는 `55,200 − 55 − 110 − 49,700 − 50 = 5,285원`이고
주식 순변화는 0이다. 전체 입력 14개를 다시 전달해도 기록 수·체결 수·경제적
값이 동일하다. 매수 취소 확인 이후의 과거 체결 재전달은 허용하지만 새 체결은
거부하고, 매도 전량 체결 이후의 새 취소 확인도 거부한다.

생성된 [`상세 보고서`](examples/stock_order_lifecycle_report.json)는 최종 스냅샷과
14단계의 상태·누적 현금 변화·고유 체결 수를 담고 있다. 가격·비용·날짜는 합성
입력이며, 실제 시세·세율·잔고·수익률을 뜻하지 않는다. 데모 DB는 이 검증용 로컬
실행에서 만들었으며 저장소에는 입력과 JSON 보고서만 기록한다.

## 독립 리뷰에서 수정한 문제

### 기존 SQLite 보조 파일 보존

메인 DB 파일이 없더라도 같은 이름의 `-wal`, `-shm`, `-journal`이 있으면
SQLite 초기화가 기존 보조 파일을 제거할 수 있었다. 세 접미사와 일반 파일·
디렉터리·심볼릭 링크·끊어진 링크의 12개 조합, 메인 파일 예약 직후 보조 파일이
생기는 경우를 실패하는 테스트로 먼저 재현했다.

이제 메인 파일 예약 전과 SQLite 초기화 전에 보조 경로를 검사하고 충돌을
거부한다. 기존 파일·대상·링크를 보존하며, 두 번째 검사에서 충돌하면 새 빈
메인 파일도 남긴다. 독립 리뷰에서 원래의 세 일반 파일 재현을 다시 실행해
기존 내용과 메인 파일 부재가 보존됨을 확인했다.

이는 기존 항목 보존 검사다. 최종 검사 이후 다른 디렉터리 작성자가 경로를
바꾸는 경쟁을 모두 차단하지는 않으므로 기존 전용 디렉터리와 미사용 DB 이름이
필요하다.

### 보고서 경로 교체 감지

JSON 저장 중 경로가 다른 파일로 교체되면 새 파일을 보존하더라도 성공으로
보고할 수 있었다. `fsync` 중 출력 경로를 교체하는 회귀를 먼저 실패시킨 뒤,
쓰기 전과 동기화 후 열려 있는 파일의 장치·inode를 경로와 비교하도록 수정했다.
교체를 발견하면 실패하고 교체된 파일은 삭제하지 않는다.

독립 리뷰는 두 문제의 수정 후 재현을 확인했고, 문서에 명시한 오프라인 저널과
읽기 전용 관측 범위에서 미해결 Critical·Important·Minor 항목 없이 승인했다.
실제 증권 계좌·주문 검증을 승인한 것은 아니다.

## KIS 계약 확인과 엄격한 로컬 정책

공식 예시 저장소 커밋
`74b0a082fa67a0be5bf53f561719c853890ed2df`와 KIS 공개 API 스키마를 확인했다.
현재 모의 조회 transaction ID는 `VTTC0081R`이며, 모의 페이지 상한은 15건이다.
관측 도구는 `M/F`에서 두 커서를 그대로 이어 받고 `D/E`에서만 완료한다.
누락·알 수 없는 종료 값, 반복 커서, 불완전 페이지, 중복 주문 식별자는 전체
실패로 처리한다.

공식 예시에 있는 재귀 인자 순서 문제나 `cnc_cfrm_qty` 오타를 그대로 따르지
않고 요청을 명시적으로 구성하며 공개 스키마의 `cncl_cfrm_qty`를 사용한다.
자세한 근거 링크와 각 필드의 로컬 정책은
[`KIS 주문 조회 가이드`](KIS_VTS_ORDER_SNAPSHOT.md#primary-contract-sources)에 있다.

공개 스키마만으로 평균가의 모든 소수 정밀도, 취소 플래그의 완전한 열거,
주문 시각의 전체 문법을 확정하지 않았다. 코드의 수용 범위는 보수적인 로컬
정책으로 명시했다. 전체 계좌 종목을 요청하지만 응답 중 6자리 주식 코드
범위를 벗어나는 기록이 하나라도 있으면 전체 결과를 거부한다.

페이지 완료는 수집 중 주문 상태가 바뀌지 않았다는 보장이 아니다. 응답의
누적 체결·잔량으로 개별 체결을 만들지 않으며, 잔량 0을 전량 체결로 간주하지
않는다. 인증·계좌 연결·실제 API의 현재 응답 형태를 검증한 결과도 아니다.

부분 체결·취소·잔고 대조는 수행하지 않았다. 이 단계에는 인증 정보와 증권사별
개별 체결·주문 관계·역전 통지·세금·거래일 검증이 필요하다. 이번 결과로
실거래나 실제 모의 주문 전송을 활성화하지 않는다.
