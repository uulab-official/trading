# AI 자동매매 플랫폼 고도화 계획 (2026-10-31)

## 현황
기존 trading 모노레포를 유지한다. README 기준 검증된 실행 경로는 합성 캔들 기반 오프라인 모의거래이며, 실시간 거래소 연동 및 실거래 운영은 검증되지 않았다. 기존 Rust 대시보드와 Python 오프라인 체크포인트도 연결되어 있지 않다.

## 목표
시장 데이터 → 캔들/거래량 → 시장 구조(SMC) → 전략/AI 보조 평가 → 리스크 승인 → 모의 체결 → 성과 분석 → 승인된 실거래 어댑터.

## 우선순위
1. 현재 테스트/CI/오프라인 회귀 검증을 유지하며 코드 감사, 경계 정리.
2. 단일 이벤트 모델: OHLCV, Tick, Signal, RiskDecision, OrderIntent, Fill, Position, EquitySnapshot. UTC timestamp, decimal 가격/수량, 거래소별 precision 및 주문 멱등키.
3. 스마트머니: swing high/low, BOS/CHOCH, FVG, order block, liquidity sweep, multi-timeframe confluence. 미래 데이터 참조 금지 및 지표별 단위 테스트.
4. 백테스트: 다음 봉 체결, 수수료/슬리피지/스프레드, 생존 편향 및 룩어헤드 검사, walk-forward/out-of-sample, drawdown, Sharpe, turnover, exposure.
5. 모의매매: 실시간 공개 시장 데이터 수집과 연결 끊김 복구, 중복 봉 제거, 주문 상태 머신, 재시작 후 reconciliation, 대시보드 조회 API.
6. AI는 설명·시장 국면 분류·전략 후보 비교에 우선 활용. AI 단독 주문 승인 금지. 재현 가능한 룰과 위험 한도를 주문 전 강제.
7. 리스크: 기본 live=false, 현물/레버리지 1배 우선, 주문당 손실 한도, 일일 손실 한도, 최대 노출, 중복 주문 방지, stale-data 차단, 킬 스위치, 비밀키 암호화 및 출금 권한 금지.
8. UI: 전략/차트/신호 근거/백테스트/모의 포트폴리오/주문 감사로그/위험 상태/긴급 중지. 로컬 실행 우선, Cloudflare는 정적 대시보드 옵션. 실시간 실행기는 지속 가동 가능한 사용자 PC/러너에 둔다.
9. 거래소별 어댑터는 별도 플러그인으로 분리. 실거래는 테스트넷 및 명시적 승인, 운영 체크리스트와 리허설 이후에만 허용.

## 수용 기준
- 오프라인 기존 테스트 통과
- 동일 입력/설정/시드로 동일 백테스트 결과
- 룩어헤드 방지 검증
- 데이터 중단/중복/지연 시 신규 주문 차단
- 재시작·네트워크 장애 시 주문 중복 없음
- 수수료 포함 잔고 및 손익 일치
- paper와 live 실행 경로가 명확히 분리되고 live는 기본 비활성화
- UI는 실제 실행기의 상태만 표시하며 임의의 성과나 거래를 생성하지 않음

## 구현 지침
기존 packages/core, data, strategy, backtest 및 apps/server 구조를 우선 재사용한다. 새 저장소나 중복 엔진을 만들지 않는다. 각 단계마다 테스트·문서·실행 증거를 커밋한다. 수익률 보장이나 검증되지 않은 '실거래 준비 완료' 표현을 금지한다.
