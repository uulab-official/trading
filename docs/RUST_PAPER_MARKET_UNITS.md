# Rust 모의매매 종목 정밀도 엔진

## 목적 및 범위

`core::market_units`는 외부의 십진 문자열을 기존 `PaperLedger`의 정수 lot,
lot당 quote atom 및 총 수수료 한도로 정확하게 변환하는 별도 개발 모듈이다.
실제 거래소 메타데이터 조회, 주문 요청, 체결 생성, Worker 활성화는 하지 않는다.

- 계좌별 quote currency 및 정밀도(0~18자리)를 명시한다.
- 종목마다 균일한 tick, lot, 최소/최대 주문 수량, 가격 범위, 최소/최대
  주문 명목 금액을 명시한다. 명목 금액은 수수료 제외 가격 × 수량이다.
- 문자열은 부호, 지수, 공백 없이 ASCII 숫자와 선택적 소수점만 사용한다.
  소수 자릿수 최대 18, 입력 길이 최대 64. 모든 값은 정수 u128 연산,
  최대공약수 약분 및 checked arithmetic으로 변환하며 결과는 u64다.
  입력이 격자에 맞지 않거나 값이 표현 범위를 넘으면 오류다. 자동 반올림 없음.
- tick × lot × 10^quote_scale이 양의 정수 atom이 아닌 상품 규칙은
  등록을 거부한다. 임의로 올림/내림하거나 부동소수점으로 변경하지 않는다.
- 종목 규칙은 등록 이후 교체할 수 없다. 단일 quote 계좌에서 동일 base
  자산의 중복 등록을 거부하며, 다른 통화 계좌에 대한 변환도 거부한다.

## 모의 주문 및 체결 경계

`MarketCatalog::order_terms`는 주문 수량, 가격, 수수료 한도를
`OrderTerms`로 변환한다. `fill_event`는 명시적으로 주입된 **합성**
체결의 가격, 수량, 수수료를 원장 이벤트로 변환하고 매수/매도 가격 한도,
원래 주문 수량·수수료 상한을 확인한다. 부분 체결에는 최소 주문 금액과
최소 주문 수량을 다시 요구하지 않는다.

수수료는 호출자가 정확한 quote 문자열로 제공한다. 수수료율, 거래량,
슬리피지, 체결 확률 또는 체결 시점을 추정하지 않는다. 실제 누적 체결량,
누적 수수료, 예약, 손실 한도 및 중복 이벤트의 최종 판단은 여전히 원장만
담당한다. 호출자는 반드시 원장에 기록된 주문 조건을 사용해야 한다.
단위 변환 API가 기존 원장의 직접 이벤트 호출을 자동으로 막지는 않는다.

예시: 테스트용 BTC/USDT, quote atom 10^-8, lot 0.00001, tick 0.01이면
한 tick × 한 lot는 10 atom이다. 0.00003 BTC × 40000.01 USDT/BTC는
3 lot × 40,000,010 atom/lot = 120,000,030 atom(1.20000030 USDT)이다.
원장 저장 값과 시장에 표시하는 가격의 단위가 다름에 유의한다.

## 아직 남은 운영 요건

- 현재 테스트 규칙은 합성 fixture다. 실제 종목·거래소별 최신 호가 규칙,
  가격 구간별 가변 tick, 시장가 주문 필터, 동적 제한은 별도 어댑터로 구현해야 한다.
- 기존 PaperConfig와 SQLite schema는 quote asset만 저장하고 quote scale,
  lot/tick 및 규칙 버전을 저장하지 않는다. 따라서 운영 통합 전에는
  카탈로그의 정규 직렬화와 digest를 계좌/백업/체크포인트에 결합하고,
  설정 변경 또는 통화·종목 단위 불일치를 fail-closed로 차단해야 한다.
- 서로 다른 venue의 동일 base 자산은 별도 계좌 또는 명시적인 상품 식별
  모델이 필요하다. 기존 보유 자산의 lot 정의를 변경하면 안 된다.
- 입력 소스의 유효성, 수수료 정책, 실제 데이터의 신선도, 위험 평가,
  주문 시뮬레이션과 CLI/Worker/대시보드 통합은 미구현이다.
- 현재는 합성 모의매매 개발 단계로, live 모드는 비활성 상태다.

## 검증

```sh
cd apps/server
cargo test --locked --test market_units_test
cargo test --locked
```

신규 테스트 11개는 코인·정수 통화 주식 예제, 정확한 변환과 원장 적용,
형식·격자 오류, 주문 제한, 등록 오류, 통화·종목 불일치, 부분 체결,
누적 수수료 거부, u64 경계, 10의 거듭제곱이 아닌 tick/lot을 다룬다.
위 명령은 실행 절차이며 검증 결과를 의미하지 않는다.
